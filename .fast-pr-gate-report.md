# Fast PR Gate — Implementation Report

## New `core-gate` Job YAML

```yaml
core-gate:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - name: Install dependencies
      run: sudo apt-get update && sudo apt-get install -y cmake build-essential libcmocka-dev
    - name: Configure
      run: cmake -S . -B build -DBUILD_TESTING=ON
    - name: Build
      run: cmake --build build -- -j$(nproc)
    - name: Run core unit tests
      run: ctest --test-dir build --output-on-failure -E '^test_integration$'
```

No `docker build` step — runs entirely on the hosted `ubuntu-latest` runner.
`libcmocka-dev` is the only extra apt package required (cmake and gcc are
already present on the runner; installing them via `build-essential` is
belt-and-suspenders).

### Excluded test

`test_integration` (ctest test #53) is the C integration test that requires the
host simulator and a live socket connection. It is excluded via
`-E '^test_integration$'`. The Python integration suite and the host-simulator
loopback remain in the `integration-tests` job only.

## Heavy Jobs Gated Off PRs

Every existing job (`static-analysis`, `build-posix`, `coverage`, `build-zephyr`,
`integration-tests`) now carries:

```yaml
if: github.event_name != 'pull_request'
```

They still run on `push` to `main`/`develop` and on the nightly schedule
(`cron: '0 3 * * *'`). They are never triggered by PR events.

## Trigger Block

```yaml
on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main, develop ]
```

## Branch Protection Note

**This file cannot change GitHub branch protection rules** — that is a
repository setting.

After merging this branch, update the branch protection rule for `develop` (and
`main`) in **Settings → Branches → Branch protection rules**:

1. Remove the existing required status checks (`static-analysis`, `build-posix`,
   `coverage`, `build-zephyr`, `integration-tests`) from the required-checks
   list, OR simply replace them with a single entry:
   - **`core-gate`**
2. Keep "Require status checks to pass before merging" enabled.
3. The heavy jobs continue to run post-merge (push trigger) and nightly, but
   they no longer block PR merges.
